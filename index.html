On quote numbers

Sequential and unique means a counter that survives two employees pressing the button at the same second. A database row with a lock, not a timestamp and not a random string, because two identical quote numbers in a customer's inbox is the one bug nobody forgives.

"Partner costs must never appear" is an architecture decision

Hiding the column in the template is the obvious reading, and it is the one that leaks. A PDF keeps its text layer whether or not the text is visible, and anyone can select it, copy it, or open the file in a text editor.

What usually gets built

One endpoint, both prices, customer column hidden at render time.

// what the browser receives { "line": "Entegrity Lever Set", "qty": 22, "msrp": 62500, "partnerCost": 48750 } // customer PDF template <td style="display:none"> $487.50 </td>

The number ships anyway It is in the page source, in the network tab, and in the generated PDF's text layer. Select-all and paste into a text editor and there it is. Nothing warns you, and the PDF looks correct.

What I would build

Two paths. The customer path never holds the number at any point.

// customer PDF request POST /quote/123/customer.pdf // server-side query, MSRP only SELECT line, qty, msrp FROM quote_lines WHERE quote_id = 123 // partner cost is a separate // query, used only by the // internal screen

There is nothing to leak The PDF is rendered server-side from a result set that never contained partner cost. No hidden element, no client-side maths, no stripping step that somebody can forget.

1
The customer PDF is built on the server, never in the browser

Client-side PDF generation needs the data in the browser to build the file. That alone puts partner cost one developer-tools tab away from the customer.

2
Separate query, not a filtered object

Fetching everything and deleting fields before rendering works until someone adds a field. A query that cannot return the column cannot leak the column.

3
Metadata gets cleared too

PDF producer strings, document properties and any template comments. Small, and the sort of thing that shows up in a security review long after launch.

4
An automated test that reads the finished file

Part of the handover: a test that generates a customer PDF, extracts its full text layer, and fails if any partner figure from that quote appears anywhere in it. It runs on every change, so the guarantee survives the next developer.

How you verify it yourself

Open any customer PDF the system produces, press select-all, paste into a text editor, and read what comes out. That is the whole acceptance test, and you can run it without me.

What stays locked

You said no employee price overrides and no additional discounts. That means the quote screen has no editable price field at all, rather than a field that validates. A control an employee cannot reach is the only one that cannot be worked around, and it also keeps every quote reproducible from its inputs.

Two logins

One shared employee login and a separate administrator login, as you specified. Worth knowing the trade-off: a shared account means a quote cannot be attributed to a person beyond the prepared-by field they type themselves. That is fine for now and awkward later, so the schema records a user id from day one even though the login is shared. If you ever move to individual accounts, the history is already there.

1
Tier boundaries

At exactly ten units, does the break apply? Workbooks routinely use > in one formula and >= in another, and the two disagree on precisely the quantities customers order most.

2
Where rounding happens

Round each line then sum, or sum then round once. On a long quote the two differ by cents, which is enough to fail a comparison against the workbook and enough to annoy accounting.

3
Flat versus percentage

A flat per-unit break and a percentage tier give different answers depending on order, which is what the panel shows. Two percentages would not, which is why this one hides so well.

4
Values typed where rules belong

A price pasted into a cell that should be a lookup. It works until the lookup changes and that one cell does not, and nothing flags it.

5
Custom finishes and SmartKeys

Your brief names both as test cases. Is a finish upcharge discountable? Are SmartKeys priced per pack or per credential, and do they attract the quantity break? These have answers; they just are not written down anywhere yet.

Recurring costs: none

You asked to have this disclosed.

No paid plugins, no licences, no per-document fees PDF generation uses a pure-PHP library (Dompdf, LGPL, free). WordPress is GPL, so that is clean to ship. No cloud PDF service, which would charge per document forever. No premium plugin dependencies. The only ongoing cost is the hosting you already pay for.

Hosting: two things to confirm

Both are usually fine, both are worth checking before we start.

PHP version and memory limit PDF generation is the one memory-hungry operation here. A long price list on a tight memory limit is the classic failure. I would rather check your actual limits in week one than discover it at milestone four. No server binaries are needed, which is why I would not use a wkhtmltopdf-based approach on shared hosting.

Excluded, so it is in writing

Also excluded: data migration of historic quotes, integration with any CRM or accounting system, and the writing of your terms text, which I will place but not author.
